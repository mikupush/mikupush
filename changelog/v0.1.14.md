# Changelog

### Added

- Client-side file encryption using AES-256-GCM, enabled by default and configurable for each selection of files or folders.
- A randomly generated key for each upload, included in the shared link's fragment (`#…`). Keys are also stored in the local upload history through a new database migration.
- An upload preferences dialog to enable or disable encryption and save defaults for future uploads without changing active transfers.
- An “Ask for preferences before each upload” option, disabled by default. Applies to file and folder selection, drag and drop, and sharing requests through application deep links.
- Spanish and English translations for the new preferences and error messages.

### Improved

- File reading and encryption in 8 MiB blocks, supporting both single-request and chunked uploads. The size reported to the server includes encryption overhead.
- Validation of all selected paths before starting transfers, with queued preferences dialogs for multiple selections.
- Upload preferences and encryption keys are preserved when preparing compressed archives and retrying uploads.
- Build configuration enabling ARMv8 AES and POLYVAL implementations on `aarch64`.

### Fixed

- Upload speed calculation now uses the actual elapsed time between measurements, including the first sample, and handles zero-duration intervals and non-increasing byte counters.
